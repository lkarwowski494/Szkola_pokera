# Strategia testów: Szkoła Pokera (rola 07 Jakość, build)
Stan: **E1 (rejestr ryzyk z wyroczniami), 2026-11-04**, baza `38983d0` na `claude/sleepy-brahmagupta-2065nu`. Sekcje 3–9 powstają w E2–E4. Raport E0: `docs/jakosc/00-rozpoznanie.md`.

## 1. Macierz możliwości środowiska
Bez zmian względem E0 (`00-rozpoznanie.md` §1, dowody z 2026-11-04). Skrót: Node 22 + Vitest + Jest/RNTL + `node --test` + fast-check + `node:sqlite` dostępne w kontenerze; Stryker, ESLint, Maestro, Detox, `xcodebuild`, emulator — niedostępne tu; E2E iOS tylko na runnerze `macos-26` (repo publiczne: 0 USD) albo u właściciela; telefon tylko właściciel.

## 2. Rejestr ryzyk
Skala skutków S1–S3 i priorytety według wzorców roli (S1 = dane, prywatność, główny przepływ, odrzucenie w sklepie; S2 = błędna liczba lub twierdzenie, funkcja poboczna, bariera dostępności; S3 = szlif). Prawdopodobieństwo: realny / brzegowy / teoretyczny. Priorytet: **wysokie** = S1 realne lub brzegowe (dane, prywatność, bezpieczeństwo także teoretyczne) oraz S2 realne; **średnie** = S2 brzegowe i S3 realne; **niskie** = reszta.

Wyjątek nazwany (D-168): błędne liczby i twierdzenia, których aplikacja uczy, oraz polityka sklepu dostają priorytet **wysokie** także przy prawdopodobieństwie brzegowym, bo blokują wydanie według reguły właściciela z 9.10.2026 (`CLAUDE.md`, „Audyty i wydania” pkt 1) i tabeli „Blokery wydania” (`docs/brd/README.md`).

Miejsca: **Node** = `pnpm run ci` lokalnie i w CI (ubuntu); **macOS** = E2E Maestro w CI (`macos-26`); **telefon** = krok właściciela (TestFlight). Kolumna „Test / status”: ID planowanego testu akceptacyjnego (`AK-<ID kryterium>`, powstaje w E3) albo istniejąca kontrola.
